# REPRODUCE.md — rebuilding the Phase 4 headline numbers

Written for Task C5 of `docs/tasks/phase4-strengthening/PHASE4_STRENGTHENING.md`
(session 4b). Nothing in this directory is needed to *interpret* the results; it
exists so that a reader can re-derive the headline numbers from the cached files
and see whether they still come out the same.

## What is in here

| file | what it is |
|---|---|
| `requirements.lock` | `pip freeze` of `venv` (92 packages) as of 2026-10-04 |
| `required_inputs.tsv` | every file the headline numbers depend on, and what for |
| `headline_expectations.tsv` | the expected value of each headline, and **where it is recorded** |
| `rebuild_headlines.sh` | rebuilds the headline numbers and prints a PASS/FAIL table |
| `runs/` | the output of the last run (created by the script; safe to delete) |

The data are **not** in git and **not** in this directory. Every CSV the analyses
read is listed in `required_inputs.tsv` with its sha256 in
`data/processed/DATA_SHA256_MANIFEST.txt` (1,955 files, regenerated by session 4b).

## How to run it

```bash
# 1. environment (the venv is gitignored; this is how you recreate it)
python3 -m venv venv
venv/bin/python3 -m pip install -r reproduce/requirements.lock

# 2. data -- restore from Arnav's archive, then add what the archive lacks (see below)
tar -xzf ~/Desktop/mthfr_data_backup.tgz -C <repo>

# 3. rebuild
bash reproduce/rebuild_headlines.sh                 # full: N_BOOT=10000, ~50 min
bash reproduce/rebuild_headlines.sh --quick         # N_BOOT=300; CIs will NOT match, points and words must
bash reproduce/rebuild_headlines.sh --only=inputs,indep,S,N,L
```

Exit code 0 iff every requested check reproduced its logged value. The script
**never** edits `headline_expectations.tsv`: a failing check is a result, and
adjusting the expectation to make it pass would be exactly the thing AGENTS 0
forbids.

## What it checks

1. **Environment** — the `venv` interpreter, `pip freeze` against the lock, and the
   versions of numpy / pandas / scipy / sklearn / patsy / statsmodels / openpyxl.
   Here: Python 3.14.3, macOS-26.5.1-arm64, numpy 2.5.3, pandas 3.0.5,
   scipy 1.18.1, sklearn 1.9.1, patsy 1.0.3.
2. **Inputs** — each path in `required_inputs.tsv` reported PRESENT or ABSENT,
   with the reason each one is needed.
3. **Independent recompute** — `scripts/176_phase4b_independent_recompute.py`, the
   second implementation written for C2 that calls no staged Phase-4 script. Its
   own 40-comparison PASS/FAIL table is the strongest single check here.
4. **Modules N and L** — scripts 172 and 174 are re-run and eight / five printed
   headline values are compared with the logs.
5. **Module S** — script 166.
6. **Modules M, U, G** — scripts 167 / 168 / 169, off by default because they are
   long and need inputs a restored archive may not carry; enable with
   `--only=...,M` (and `U`, `G`).

## Result of the session-4b tests, recorded honestly

**On the working tree, with all inputs present: `RESULT: PASS`, 0 checks failed.**
That run covered inputs, the independent recompute, and modules S, N and L: 40
independent comparisons (39 identical, 1 documented exception) and all 14 printed
N/L/S headline values reproduced.

**In a fresh clone under `/tmp` with only Arnav's archive: `RESULT: FAIL`.** Two
independent reasons, both real and neither fixable from inside this package:

1. **The archive is missing 12 of the 19 required inputs.** It contains
   `data/processed/phase2/`, `phase2_diagnostics/` and `phase3/` only (702
   entries, 30,126,816 bytes, sha256
   `225106698afa8bd82a6ac080a2ecb82f3856186e70fc1658a79ff5afe9c42d50`). It has
   **no** `data/raw/`, **no** `esm2_wt_scores.csv` / `esm2_a222v_bg_scores.csv`,
   **no** `task82_ae_raw.csv` / `task69_w2_bg_raw.csv` (the two files that define
   the held-out frame H), **no** `data/processed/phase4/` at all, and **no**
   `data/external/` (MaveDB maps, the Weile et al. supplement, 1PGA). Without the
   H-definition files every module stops immediately at
   `FileNotFoundError: task82_ae_raw.csv`, so no headline number can be rebuilt.
2. **Commit `24fe0e9` does not contain the code.** Its message reads "Phase 4:
   staged scripts, amendments, build log and cached-module results
   (READY-TO-LAUNCH)", but `git show --stat HEAD` lists **23 files, all of them
   `PHASE4_A*_OUTPUT.txt` run logs**. None of `scripts/165`–`scripts/175`, none of
   this `reproduce/` directory, and neither `PHASE4A_BUILD_LOG.md` nor
   `STATE_FOR_LAUNCH.md` is in that commit. A fresh clone therefore has no
   `reproduce/rebuild_headlines.sh` to run at all.

To make the test meaningful the working tree's uncommitted files were overlaid onto
the clone with `rsync` (scripts, `reproduce/`, `docs/tasks/phase4-strengthening/`)
and `venv` was symlinked in place of `pip install -r requirements.lock`. Both
substitutions are recorded here rather than hidden; with them the script ran and
failed only on the missing data, which is the honest result.

## What must be added to the archive to make this reproducible

`data/raw/` (the folate model table and 6FCX.pdb), `data/processed/esm2_wt_scores.csv`,
`data/processed/esm2_a222v_bg_scores.csv`, `data/processed/task82_ae_raw.csv`,
`data/processed/task69_w2_bg_raw.csv`, the whole `data/processed/phase4/` tree
(roster, 50 neighbour score files, manifest, driver state and logs) and all of
`data/external/`. `data/processed/DATA_SHA256_MANIFEST.txt` lists every one of
these with its sha256 so the restored copies can be verified.

## Known non-reproducible items, and why

- **M-3 / M-4 (the simulation null and the planting curve).** C2's attempt to
  re-draw the null failed its own identity gate, so `scripts/167` is the only
  implementation of that generator in the project and its numbers are not
  independently reproduced here. See `PHASE4B_MORNING_LOG.md` [C2].
- **Module G's G-1 / G-2 statistics** depend on script 155's per-(background,
  partner) table, which is not cached on disk; only the frozen mean `rho_b` target
  is verifiable.
- **Module L's 150M and 35M columns and both cross-model agreements** need night B,
  which has not been run; there is nothing to rebuild.
- **Bootstrap CIs** are random draws. `--quick` will not reproduce the logged
  intervals; only the point estimates and the outcome words are expected to match.
